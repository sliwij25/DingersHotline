# Strikeout Leaders Page — Design Spec

**Date:** 2026-08-20
**Scope:** Sub-project 2 of 4 (Over/Under logic [done] → Strikeout Leaders page →
K hit-rate pipeline+page → site nav reorg). This spec covers only the
Strikeout Leaders page.

## Problem

The site has a "Home Run Leaders" page (`docs/leaderboard.html`, generated
by `generate_leaderboard_html()` in `tools/generate_html.py`) showing the
top 50 batters by season HR count with Statcast context stats. There is no
equivalent leaderboard for pitchers' strikeout totals.

## Goal

A new page, structurally and visually parallel to HR Leaders, ranking
pitchers by season strikeout total with supporting rate stats.

## Non-goals

- No new scoring/ranking model — this is a pure display of season totals,
  unrelated to `agents/k_predictor.py`'s Over/Under prediction pipeline.
  `notes/ALGORITHM.md` does not need an update.
- No odds/EV/price display.
- K hit-rate tracking and site nav reorg are separate follow-on specs.

## Design

### 1. Data source

New Savant custom-leaderboard fetch in `tools/generate_html.py`, following
the exact pattern of the existing batter fetch in `generate_leaderboard_html()`
(cache-first, BOM-strip via `.lstrip("﻿")`, MLB Stats API team-ID→abbreviation
batch lookup via the existing `_TEAM_ABBREV` dict):

```
https://baseballsavant.mlb.com/leaderboard/custom
  ?year={season}&type=pitcher&filter=&sort=4&sortDir=desc&min=20
  &selections=strikeout,k_percent,whiff_percent,p_formatted_ip
  &chart=false&r=no&exactNameSearch=false&csv=true
```

- **Sort/rank:** `strikeout` (season total Ks), descending. Top 50. Tied
  ranks handled identically to HR Leaders — `display_rank` only advances
  when the `strikeout` value changes vs. the previous row.
- **Filter:** `min=20` (innings pitched) — distinct from HR Leaders' `min=5`
  (plate appearances). Keeps small-sample relievers with a couple of good
  outings off a 50-pitcher season-total board.
- **K/9** is computed, not fetched: `strikeout * 9 / p_formatted_ip`.
  Savant's custom leaderboard has no direct K/9 column.
- **Cache path:** `cache/statcast_pitcher_leaders_{today_str}.csv` — a new,
  distinct cache file from k_predictor.py's own
  `cache/statcast_pitcher_k_{today_str}.csv` (different selections,
  different consumer, no reason to couple them).

### 2. Columns

`# / Player / Team / K / K% / Whiff% / K/9`

- `K` (season strikeout total) is the hero stat — bold, same styling as
  HR Leaders' `HR` column (`.td-hr` equivalent, e.g. `.td-k`).
- `K%`, `Whiff%`, `K/9` are percentile-colored using the existing
  `_thresholds()` / `_cell_class()` helpers (green = top third, yellow =
  middle third, red = bottom third), computed independently per column
  exactly as HR Leaders does for Barrel%/xISO/EV Avg.
- Name formatting (`_fmt_name`, "Last, First" → "First Last") and team
  abbreviation lookup reuse the existing helpers as-is.

### 3. Page function

New function `generate_strikeout_leaderboard_html(today_str: str | None = None) -> str`
in `tools/generate_html.py`, placed near `generate_leaderboard_html()`. It is
a structural copy of that function:

- Same CSS custom properties, Google Fonts, site-header (inline SVG
  baseball icon, "Dingers Hotline" title), nav-links, footer/disclaimer.
- `.site-date` text: "Season K Leaders · Updated {date}".
- `.page-title`: "2026 Strikeout Leaders".
- `.page-subtitle`: "Top 50 · Statcast data · Updated daily with morning picks".
- `.metric-defs` legend with per-stat definitions:
  - **K%** — "Elite swing-and-miss rate" (top-third threshold shown dynamically, same pattern as Barrel%).
  - **Whiff%** — "Empty swings per swing taken".
  - **K/9** — "Strikeouts per 9 innings — traditional rate stat".
- Mobile responsive rules (`@media (max-width: 600px)`) identical in
  structure to HR Leaders' (hide `.col-stat` columns, collapse
  `.td-player` min-width).

### 4. Output & wiring

- Written to `docs/k-leaderboard.html`.
- `scripts/daily_picks.py`: import `generate_strikeout_leaderboard_html`
  alongside the existing `generate_leaderboard_html` import; call it and
  write `docs/k-leaderboard.html` right after the HR leaderboard is
  written; add `docs/k-leaderboard.html` to both existing git-add file
  lists (currently at lines 708 and 717).
- **Nav-link:** `<a href="k-leaderboard.html">K Leaders</a>` added
  immediately after the existing "K Picks ⚾" link, in every place the nav
  bar is defined or hardcoded:
  - `tools/generate_html.py`'s shared header template (used by all
    generator functions — the 3 in-file locations previously identified at
    lines 1127, 1634, 2255 all render from the same header markup, so this
    is one edit propagated by re-running the generators, not three
    separate template edits).
  - Static already-generated pages that hardcode nav markup and won't be
    regenerated by this change alone: `docs/hit-rate.html`,
    `docs/index.html`, `docs/mockup-pnl.html`, `docs/pick-of-the-day.html`,
    `docs/player-card.html`, `docs/strikeouts.html` — each gets the same
    nav-link HTML inserted by direct edit.

### 5. Testing

- Unit-test the K/9 computation and tie-handling rank logic with a small
  synthetic CSV-row fixture (mirroring however HR Leaders' equivalent
  logic is tested today, if it has existing tests — otherwise a new
  focused test module).
- Manual verification: run `python scripts/daily_picks.py --use-cache`
  and open `docs/k-leaderboard.html` — confirm 50 rows sorted by K
  descending, percentile coloring on K%/Whiff%/K/9, and that "K Leaders"
  appears in nav on every page alongside "K Picks".
